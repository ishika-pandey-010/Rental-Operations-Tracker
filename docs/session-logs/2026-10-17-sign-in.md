# Sign up and sign in, 2026-10-17

## What the user needs
A landlord with a few units wants their own account so tenant details and rent records stay private, and wants to get back in quickly next month.

## What the docs said
- FR-01 ([PRD §6.1](../PRD.md#61-functional)): sign up, sign in and sign out with email through Supabase Auth.
- US-01 ([user-stories.md](../user-stories.md#us-01-sign-up-and-sign-in)): AC1 lands on an empty dashboard, AC2 "Email or password is incorrect", AC3 signed-out visitors are sent to sign-in.
- UAT cases TC-AUTH-01 to TC-AUTH-05. TC-AUTH-04 (duplicate email) and TC-AUTH-05 (deep link returns you to the page) go beyond the story's AC; I treated them as part of it.

## Plan
Build email and password auth with server actions, a middleware that guards every page except `/signin` and `/signup`, and a home page. Left out on purpose: password reset (not in any story; noted as friction below), and the dashboard totals, which are US-23 in S3. The home page is a four-step getting-started list instead (OQ-07).

## Tests written
End-to-end (`e2e/auth.spec.ts`), one per AC and UAT case plus four of my own:
- TC-AUTH-01 sign-up lands on the home page with "Add your first property".
- TC-AUTH-02 wrong password shows the message, keeps the email, stays on sign-in.
- TC-AUTH-03 after sign-out, `/leases` redirects to `/signin?next=%2Fleases`.
- TC-AUTH-04 a second sign-up with the same email says "An account with this email already exists. Sign in instead." with a link.
- TC-AUTH-05 a lease URL opened while signed out comes back after sign-in.
- Short password, signed-in visitor on `/signin`, an off-site `next` value (`//evil.example.com`), and keyboard-only sign-in.

Unit (`tests/unit/auth.test.ts`): `safeNext` refuses off-site redirects; `authErrorMessage` maps Supabase error codes, including a network failure, to plain sentences.

First failures: the unit tests failed on the missing `@/lib/auth` module; the end-to-end suite couldn't build because no app existed. After the first build, three end-to-end tests failed for a reason that had nothing to do with the feature: Next.js renders its own route announcer with `role="alert"`, so `getByRole("alert")` matched two elements. The tests now look for the alert inside `<main>` (`alertIn` in `e2e/helpers.ts`).

## What I built
- `src/app/auth/actions.ts`: `signIn`, `signUp`, `signOut` server actions. Errors come back as form state with the typed email, so the form never clears on failure.
- `src/lib/auth.ts`: `safeNext` and `authErrorMessage`.
- `src/lib/supabase/middleware.ts` and `src/middleware.ts`: session refresh and the redirect rules.
- `src/app/(app)/layout.tsx`: top bar with the main nav and Sign out.
- `src/app/globals.css`: one stylesheet with light and dark colour tokens and a visible focus ring.

## User review
- Main task: create an account from the sign-in page, then sign back in after a typo in the password.
- Sign-up: 2 clicks ("Create an account", "Create account"), 2 fields, 2 screens. No change; I couldn't find a step to remove.
- Sign-in after a wrong password, before review: the cursor went back to Email, so it took Tab, the password, and Enter. After review: the cursor lands in Password, so it's the password and Enter. One keystroke saved, and more to the point the landlord doesn't type the password into the email box.
- At 390 px wide the four nav links stacked into a column 150 px tall above the page. They now sit in one scrollable row under the brand. A test checks the nav height and that nothing scrolls sideways.
- Feedback: the submit button changes to "Signing in…" while the request runs. In the end-to-end run the whole keyboard sign-in test, typing included, took 779 ms.
- Remaining friction: there's no "forgot password" link. No story asks for it and it needs email sending, which the hosted plan hasn't set up (OQ-16). It's the first thing a real landlord will look for.
